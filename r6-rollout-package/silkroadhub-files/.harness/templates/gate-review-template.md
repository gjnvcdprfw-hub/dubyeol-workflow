> 작성자: [Foreman] (SUB-3 단계, [Reviewer]·[Judge] 호출 결과 종합)

> Tier A: [Reviewer] + [Judge] 둘 다 필수

## 0. 정보 격리 원칙 (재확인)

본 gate-review는 [Reviewer]와 [Judge]를 **별도 세션·다른 정보로** 호출한 결과를 종합한다.

| 역할 | 입력으로 받음 | 입력으로 받지 않음 |
|---|---|---|
| [Reviewer] | 코드 변경분, 기술 명세, 테스트 결과 | 의도 배경, 사업 맥락 |
| [Judge] | task-card §1·§3 의도, handoff §1 산출물 요약, 의도 정렬 증거 | 코드 디테일, 명령어 |

같은 모델이라도 *반드시 다른 세션*. 한 인스턴스가 두 모자 금지.

---

## 1. [Reviewer] 섹션 — 기술적 정합성

### 1.1 호출 정보

- **호출 일시**: YYYY-MM-DD HH:MM
- **도구·세션**: 지피티 [Reviewer] 세션 / 코덱스 (도구 불가 시 사유)
- **모델·세팅**: gpt-5.5, temperature 파라미터 생략 (Codex 시: 해당 버전)
- **입력 자료 목록**:
  - handoff §2.2 변경 파일 목록
  - handoff §3 진행 이력
  - 필요 시 diff 발췌 (마스킹 적용)
- **호출 스크립트**: `scripts/invoke_codex.sh` 또는 `scripts/invoke_chatgpt_gate.sh` (해당 시)
- **원문 저장**: `.harness/runs/<run_id>/reviewer-raw.md` (선택)

### 1.2 [Reviewer] 판정

- **종합 판정**: 통과 / 조건부 통과 / 보류 / 차단
- **사유 요약** (1~2문장):

### 1.3 기술 리스크 지적 (있으면)

| 영역 | 지적 내용 | 심각도 | 구체 근거 (파일·라인) |
|---|---|---|---|
| 아키텍처 일관성 | ... | High/Med/Low | ... |
| 보안 | ... | ... | ... |
| 성능 | ... | ... | ... |
| 사이드이펙트 | ... | ... | ... |
| 테스트 커버리지 | ... | ... | ... |

지적 시 *구체적 인용*(파일명·라인·diff) 의무. 추상적 "괜찮아 보임" 금지.

### 1.4 개선 제안 (있으면)

- [제안 1]: [내용] — 수정은 [Builder] 영역, 본 단계에서 수정하지 않음
- [제안 2]: ...

### 1.5 [Reviewer] 권한 천장 점검

- [ ] 코드 직접 수정하지 않음 (지적·제안만)
- [ ] Tier 분류 시도 안 함 (그건 [Foreman])
- [ ] 사업적 판단 안 함 (그건 [Owner]·[Judge])

---

## 2. [Judge] 섹션 — 사업적·논리적 정합성

### 2.1 호출 정보

- **호출 일시**: YYYY-MM-DD HH:MM
- **도구·세션**: 지피티 [Judge] 세션 ([Reviewer]와 *반드시 분리*)
- **모델·세팅**: gpt-5.5, temperature 파라미터 생략
- **입력 자료 목록**:
  - task-card §1 [Owner] 발화 원문
  - task-card §3 의도 정렬 증거 블록
  - handoff §1 의도 정렬 대조 결과
  - PROJECT.md §C.[N] 연결 모듈 정보
- **입력 *금지* 자료**: 코드 diff, 명령어, 기술 디테일
- **호출 스크립트**: `scripts/invoke_chatgpt_gate.sh` 또는 `scripts/invoke_chatgpt_advocate.sh`
- **원문 저장**: `.harness/runs/<run_id>/judge-raw.md` (선택)

### 2.2 [Judge] 판정

- **종합 판정**: 진행 / 수정 / 보류 / 중단
- **사유 요약** (1~2문장):

### 2.3 Devil's Advocate 질문 (제기된 것)

[Judge]가 던진 반대 논리·의심 질문 목록:

- [질문 1]: [내용] → [Foreman] 검토 결과: [답변]
- [질문 2]: ...

### 2.4 비즈니스 사이드이펙트 지적 (있으면)

- [지적 1]: [내용] / 영향받을 PROJECT.md §C.[N]: [...]
- [지적 2]: ...

### 2.5 의도 ↔ 결과 정렬 점검

| task-card §3 의도 요소 | 산출물 정렬 정도 | 의문 |
|---|---|---|
| 한 문장 목표 (What) | 완전 / 부분 / 어긋남 | [있으면] |
| Looks Like 핵심 | 충족 / 부분 / 미충족 | [있으면] |
| Looks Wrong 방어 | 방어 됨 / 부분 / 실패 | [있으면] |

### 2.6 [Judge] 권한 천장 점검

- [ ] 코드 디테일 판정 시도 안 함
- [ ] [Reviewer]와 *동일 인스턴스* 겸임 안 함
- [ ] 모델·세팅 변경 시 [Foreman] 보고함 (또는 변경 없음)
