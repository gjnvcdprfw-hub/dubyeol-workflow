### E.1 갱신 메커니즘

PROJECT.md는 **task-card를 통해서만** 갱신된다. [Foreman] 단독으로 본 문서를 임의 수정하지 않는다.

| 절 | 갱신 시점 | 갱신 경로 |
|---|---|---|
| §A 기획 맥락 | [Owner] 발화로 *카테고리 5 (기획) task* 발생 시 | 해당 task의 task-card → 본 문서 §A 반영 |
| §B 중기 목표 | 분기 종료 또는 [Owner] 발화로 *카테고리 5 task* 발생 시 | 해당 task의 task-card → 본 문서 §B 반영 |
| §C 모듈 진행 | **모든 task의 SUB-5 종료 시** | 해당 task-card의 "PROJECT.md 갱신 사항" → 본 문서 §C.N 반영 |
| §D 결정 이력 | task 진행 중 큰 결정 발생 시 | 해당 task-card에 박은 후 본 문서 §D 반영 |
| 본 문서 구조 자체 | r6 베타 회고에서 발견 시 | 다음 r 개정 task |

### E.2 변경 이력 추적

본 문서의 어느 항목이 *어느 task에서* 변경됐는지 역추적 방법:

1. 본 §E 상단의 *마지막 갱신 task run ID* — 가장 최근 1건
2. `.harness/runs/*/task-card.md`의 *PROJECT.md 갱신 사항* 섹션 — 전체 이력

## F. task-card와의 연결 (참조)

### F.1 task 시작 시 (SUB-1, task-card 작성)

task-card에 다음 필드 박음:

```
## 상위 맥락 연결 (PROJECT.md 진입 시점)
- 연결 모듈: §C.[N].[모듈명]
- 진입 시점 마일스톤: §C.[N].다음 마일스톤 중 [구체 항목]
- 이번 task로 *전진시키는 것*: [한 줄]
```

### F.2 task 종료 시 (SUB-5, task-card 갱신)

task-card에 다음 갱신 사항 박음:

```
## PROJECT.md 갱신 사항 (task 종료 시 [Foreman] 작성)

### §C.[N] 모듈 갱신
- 현재 상태: [변경 전] → [변경 후]   (변경 없으면 "변경 없음")
- 최근 마일스톤에 추가: [내용]
- 다음 마일스톤에서 완료(체크): [항목]
- 다음 마일스톤에 추가: [내용]
- 현재 막힌 점: [신규 / 해소 / 변경]

### §D 결정 이력 추가 (해당 시)
- 날짜 / 결정 / 사유 / 영향 모듈

### 본 task의 갱신을 PROJECT.md에 반영함
- 반영 일시: YYYY-MM-DD HH:MM
- PROJECT.md §E.마지막 갱신 task run ID 박은 값: [run ID]
```

[Foreman]은 *task-card의 갱신 사항을 PROJECT.md §C.N에 그대로 옮긴 후* SUB-5 종료. 옮김 누락 시 다음 task의 *상위 맥락 확인*이 부정확해짐.
